# 1000year · 천년의신화 런처

천년의신화 V1.070KR용 Windows 런처입니다. 게임 파일은 포함하지 않습니다.

## 실행

`MMyth_launcher_버전.exe`(예: `MMyth_launcher_0.7.2.exe`)를 실행하고 `MMyth.exe`가 있는 게임 폴더를 선택합니다. 런처는 게임의 `MMyth.exe`에서 아이콘을 가져와 같은 아이콘으로 표시됩니다. EXE 안에 호환 DLL, 패치 레시피와 업데이트 설치 도구가 들어 있습니다.

- **1280×720 내부 해상도 (16:9)**: 지형을 1280×720 전체에 그립니다. 오른쪽 HUD는 오른쪽 아래에 겹쳐 표시하며 자원 아이콘과 수치는 화면 오른쪽 끝에 표시합니다. 새 설치의 기본 선택입니다.
- **800×600 내부 해상도**: 지형을 800×600 전체에 그리고 HUD는 오른쪽 아래에 배치합니다. 화면 꽉 채우기와 함께 쓰면 와이드 모니터에서도 여백 없이 표시됩니다.
- **1024×768 내부 해상도 (넓은 전장)**: 지형을 1024×768 전체에 그립니다. 유닛과 타일은 원래 픽셀 크기를 유지하고 HUD는 오른쪽 아래에 배치합니다.
- **1024×768 화면 확대**: 기존 640×480 시야를 크게 표시합니다.
- **640×480 원본 해상도** 및 전체 화면(화면 비율 유지)도 선택할 수 있습니다.
- **마우스 창 가두기**: 전투 중 게임 창이 활성 상태이면 커서를 창 안에 가둡니다. Alt+Tab, 최소화, 전투 종료 시 해제됩니다.
- **화면 꽉 채우기**: 4:3 화면을 와이드 모니터 전체로 늘려 양옆 검은 여백을 없앱니다. 화면만 늘어나며 시야와 전투 규칙은 같아 멀티플레이에 영향이 없습니다. 끄면 기존처럼 비율을 유지합니다.
- 메뉴·브리핑은 원래 해상도를 유지하며 전투 진입 시 내부 해상도가 전환됩니다. 전투 중 팝업은 원래 크기로 표시됩니다.
- 시작 시 GitHub 정식 릴리스에서 새 런처를 자동 다운로드·검증·설치하고 재시작합니다. 설정에서 끌 수 있으며 인터넷 오류는 게임 실행을 막지 않습니다.
- 전장 음악은 게임 폴더의 `BGM\Track02.mp3`를 직접 반복 재생해 CD 인식 실패를 우회합니다. 일반 게임과 리플레이에 적용하며 게임의 배경음악 옵션을 따릅니다.
- 런처의 **전장 배경음악 음량** 슬라이더로 0~100%를 저장하고 실행 중에도 조절할 수 있습니다. 0%는 음악만 음소거하며 효과음은 유지합니다. 음량 기능이 없는 이전 버전으로 실행한 게임은 새 런처에서 다시 시작해 주세요.

게임은 여러 CPU 코어를 사용합니다(cnc-ddraw `singlecpu=false`). 특정 PC에서 멈춤·충돌이 생기면 `%LOCALAPPDATA%\1000year\settings.json`에 `"SingleCpu":true`를 넣어 이전처럼 한 코어에 고정할 수 있습니다.

원본 `MMyth.exe`는 변경하지 않습니다. V1.070KR 해시와 패치 전후 바이트를 검증한 뒤 `MMyth.Wide.exe`, `MMyth.HD.exe`, `MMyth.SVGA.exe` 또는 `MMyth.Portable.exe`를 생성합니다. 구형 설치 경로 대신 현재 폴더에서 파일을 읽고 시작 영상은 건너뜁니다. 최초 적용 전 `ddraw.dll`과 `ddraw.ini`를 백업하며 런처의 ‘원래 그래픽 복원’으로 복구할 수 있습니다. 설정과 로그는 `%LOCALAPPDATA%/1000year/`에 저장합니다.

## 밸런스 변경

- 0.7.2: 백제·고구려 **망루 전비 5 → 15**.
- 0.7.2: **미륵염화술**이 생체 유닛뿐 아니라 공성 병기·배에도 불벼락을 떨어뜨립니다(건물은 원래대로).
- 모든 해상도에 같은 규칙으로 적용되며, 멀티플레이는 참가자 전원이 0.7.2 이상이어야 합니다.

## 멀티플레이 해상도

0.6.13은 고해상도에서 동일 틱의 불필요한 지형 다시 그리기와 대기 반복을 줄입니다. 카메라·안개·지형·조명이 바뀌면 즉시 다시 그리며, 타이머·관전 자원 글자도 내용 변경 시에만 다시 만듭니다. 해상도와 전투 규칙은 유지합니다.

0.6.12부터 원본·화면 확대·내부 해상도 모드 모두 같은 집결지·자동 채집·유닛 생성 규칙을 사용합니다. 참가자 전원이 **0.6.12 이상으로 업데이트하고 게임을 다시 실행**한 뒤 서로 다른 해상도로 플레이할 수 있습니다. 0.6.11 이전 원본 모드와 내부 해상도 모드를 섞으면 전투 규칙 차이로 상태가 달라질 수 있습니다.

## 맵 에디터

런처의 **맵 에디터** 버튼을 누르면 게임 폴더에 `MapEditor.exe`를 만들어 실행합니다. 런처에는 게임 실행 파일이 들어 있지 않으며, 원본 `MMyth.exe`(V1.070KR) 해시와 수정 전후 바이트를 검증하는 레시피(`compat/mapeditor.json`)로 같은 파일을 만듭니다. 이미 같은 파일이 있으면 그대로 실행합니다.

## 단축키 설정

런처의 **단축키 설정**에서 부대 1~0, 명령 버튼 F1~F8, 쉬는 일꾼(`.`)·군사 유닛(`` ` ``)·영웅(Tab) 선택, 명령·생산 글자 단축키를 원하는 키로 바꿀 수 있습니다. 새 키를 누르면 원래 키의 기능이 실행되고, 바꾼 원래 키는 다른 기능에 쓰지 않으면 꺼집니다. 한 키를 두 기능에 지정할 수 없습니다.

내 컴퓨터에서 게임 창에 전달되는 키만 바꾸므로 상대에게 전달되는 명령은 같고 멀티플레이 동기화에 영향이 없습니다. 상대가 같은 설정을 쓸 필요도 없습니다. 채팅 중과 메뉴에서는 원래 키를 사용합니다. 게임이 직접 읽는 방향키·Ctrl·Shift·Alt와 Enter·Esc는 바꿀 수 없습니다.

## 연속 건설 예약

건물을 놓을 때 **Shift**를 누른 채 클릭하면 선택한 일꾼의 작업 예약에 추가되고, 건설 위치 선택 상태가 계속 유지됩니다. 성채(벽)처럼 여러 칸을 이어 놓을 때 버튼을 다시 누를 필요가 없으며, 일꾼이 놓은 순서대로 자동으로 짓습니다. 예약된 건물 자리에는 게임의 건설 미리보기가 계속 표시되고, 일꾼이 그 예약을 시작하면 사라집니다(내 유닛의 예약만, 내 화면에만 표시). 예약은 게임 기본 대기열을 사용하므로 최대 10개입니다. Shift를 누른 채 마우스 왼쪽 버튼을 누르고 끌면 지나간 칸마다 이어서 예약됩니다. 건물 크기만큼 간격을 두고, 게임의 건설 가능 판정을 통과한 칸만 예약하며, 한 번 끌 때 최대 10칸(유닛 예약 한도)입니다. Shift를 떼고 Esc 또는 오른쪽 클릭으로 끝냅니다. Shift+이동 명령은 경유지 예약이 되고, 원래 게임의 Ctrl 예약도 그대로 사용할 수 있습니다.

## 영웅 초상화

전투 중 왼쪽 위에 내 영웅의 초상화와 체력(녹색·노란색·빨간색)·마력(파란색) 막대를 표시합니다. 초상화를 클릭하면 그 영웅 위치로 화면이 이동합니다. 화면 표시와 내 카메라만 바뀌므로 게임 진행과 멀티플레이에 영향이 없습니다. 런처의 **영웅 초상화 표시**로 끌 수 있습니다.

## 선택 단축키 (내부 해상도 모드)

왼쪽 위에 `쉬는 일꾼 : N`을 표시합니다. 자신의 살아 있는 일꾼 중 이동·채집·건설·전투·예약 명령이 없는 유닛을 집계합니다.

대상은 고구려의 호민·황소 호민, 백제의 부민·황소 부민, 신라의 하호·황소 하호입니다. 생성 직후나 이동 후 멈춘 일꾼도 포함합니다.

| 키 | 선택 대상 |
| --- | --- |
| `.` | 쉬는 일꾼 전체 |
| 백틱 (`) | 군사 유닛 전체 (영웅 포함) |
| `Tab` | 영웅 전체 |

화면 밖의 유닛도 포함합니다. 채팅·일시정지·Ctrl/Shift/Alt 조합 중에는 실행하지 않습니다. 20개를 넘으면 추가 유닛도 선택 표시하고 그룹 명령을 분할 전달합니다. 원본 HUD의 초상화와 부대 번호 저장은 20개 형식을 유지합니다. 대규모 선택은 명령 대기열 상황에 따라 전달이 여러 프레임에 걸칠 수 있습니다.

## 빌드·업데이트 배포

Windows의 .NET Framework 4.x 컴파일러와 Visual Studio C++ x86 빌드 도구가 필요합니다. 리플레이 DLL은 런처 안에 포함됩니다.

런처로 시작한 경기에는 위쪽에 **경과 시간**이 표시됩니다. 리플레이 기록을 꺼도 타이머는 표시되며, 경기 일시정지 중에는 멈춥니다.

## 리플레이 (시험 기능)

관전 재생에서는 지도와 미니맵의 안개를 걷고 오른쪽 위에 참가자별 이름·쌀·나무·전비를 표시합니다. 시야·조명 공개는 화면 그리기에서만 적용하며 기록된 명령·AI 상태는 유지합니다. 야간에도 모든 진영의 지상 유닛·건물이 보이며 플레이어 알림과 영웅 초상화는 표시하지 않습니다. 기록 끝에 도달하면 완료 알림이 뜨고 확인 시 게임과 재생 창을 종료합니다.

런처의 **경기 리플레이 기록**을 켜고 게임을 시작합니다. 첫 경기의 시작 세이브와 실제 실행된 명령을 기록하며, 게임을 종료하면 `%LOCALAPPDATA%\1000year\Replays`에 `.mythreplay` 파일을 저장합니다. 런처를 먼저 닫아도 별도 저장 도우미가 마무리합니다. 다음 경기는 게임을 다시 실행해 기록하세요.

목록은 공용 저장 폴더와 게임 폴더의 `Replays`를 함께 검색하며 자동으로 갱신됩니다. **새로고침**으로 즉시 다시 검색할 수 있고 저장 개수·위치를 목록 창에서 확인할 수 있습니다.

**리플레이 목록 → 재생**을 누르거나 목록·탐색기에서 `.mythreplay` 파일을 더블클릭하면 해당 경기의 해상도와 시작 상태를 자동으로 불러옵니다. 재생 창에서 일시정지, 한 프레임 진행, 1.5·2·4배속, 게임 닫기를 사용할 수 있습니다. 게임에서 기본 속도는 1.5배속이며 숫자키 **1 / 2 / 4**(숫자패드 포함)로 각각 **1.5 / 2 / 4배속**으로 바꿀 수 있습니다. 재생 중 새 유닛 명령은 전달하지 않으며, 위치·체력·명령·자원·난수가 기록과 다르면 정지합니다. 정상적으로 끝난 경우 재생 완료를 표시합니다.

8개 플레이어 슬롯의 네트워크 수신 후 실행 명령을 기록하고, 재생은 서버 접속 없이 로컬에서 수행합니다. 실제 게임에서 단일 경기 및 8개 슬롯 시험 명령의 재생을 검증했습니다. **서로 다른 두 PC의 실제 멀티 경기 연결 검증은 아직 진행하지 않았습니다.** 기존 두 프로젝트도 실험용 어댑터라는 점을 참고하여 이 기능 역시 시험 기능으로 제공합니다.

같은 게임·패치·재생 규칙이 필요합니다. 0.6.0의 16:9 기록은 당시 실행본을 복원해 재생합니다. 시작 세이브에 지형이 들어 있으므로 별도의 사용자 지도 파일을 교체하지 않습니다. 크기·해시·프레임 연속성·명령 범위가 잘못된 파일과 비정상 종료된 기록은 목록 재생에서 거부합니다. 세션 원본은 `%LOCALAPPDATA%\1000year\R`에 보존하며, 저장에 실패한 완료 기록은 런처 시작 및 목록 열기 시 중복 없이 복구합니다. 상태 해시는 진단용이며 모든 게임 메모리의 동등성을 증명하지는 않습니다.

```powershell
./scripts/build.ps1
./tests/Run-Tests.ps1
# 원본 게임이 있는 개발 환경의 추가 검사
./tests/Run-Tests.ps1 -GameExe '게임폴더/MMyth.exe'
```

결과는 `dist/`에 생성됩니다. `src/Core.cs` 버전과 동일한 `vX.Y.Z` 태그를 push하면 GitHub Actions가 검사 후 EXE, ZIP, SHA256을 Releases에 게시합니다. 자동 업데이트는 ZIP과 파일별 SHA256을 검증하고 설치 준비 확인, 기존 버전 백업, 실패 시 롤백을 수행합니다. 게임 파일과 저장 게임은 업데이트 목록에 포함하지 않습니다. 0.1.0 런처의 업데이트 패키지 형식을 유지합니다.

## 해상도 구현과 검증 범위

다른 프로젝트(아마게돈·태조왕건)의 업데이트 구현과 아마게돈 해상도 분석에서 표면 크기, 버퍼 pitch, 지형 캐시, 안개, HUD, 클릭 판정, 미니맵 투영을 참고했습니다. 패치 주소는 이 게임을 별도로 분석했습니다.

실제 Windows에서 메뉴/백제 첫 전투 진입, 단일 선택, 드래그 선택, 확장 영역으로 우클릭 이동, 미니맵 카메라 이동, 초기 메뉴 복귀, 시험 복사본 저장·불러오기를 검사했습니다. x86 에뮬레이션으로 확장 버퍼 복사와 경계, HUD 좌표, 마우스 좌표 변환을 검사했고, 업데이트 설치·손상 거부·실패 롤백도 검사했습니다.

모든 시나리오, 장시간 전투, 멀티플레이 동기화와 모든 DPI/모니터 조합까지 검증한 것은 아닙니다. 지형 캐시는 안전한 전체 다시 그리기를 사용하므로 저사양 환경에서는 확대 모드보다 부하가 커질 수 있습니다. 내부 구현과 재생성 절차는 [analysis/RESOLUTION.md](analysis/RESOLUTION.md)를 참고하세요.
